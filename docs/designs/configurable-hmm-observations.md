## Problem Statement

`fetch_returns()` in `main.py` hardcodes close-to-close log returns. The CLI already prompts period and state count, but not **what the HMM sees**. That blocks testing options-style volatility regimes (VIX, realized vol, variance risk premium) without rewriting the fetch path each time.

## What Makes This Cool

Point the same six console tables at a **constructed 1-D gap**: VIX minus this ticker's 21-day realized vol. Then show what the **stock** did inside cheap vs expensive vol. Two sequential runs (close vs VRP) is the A/B.

## Constraints

- Builder / demo: ship in `python main.py`, for the author only
- No plots, no AIC toggle, no compare-two-recipes UI, no option-chain data
- Stay in `main.py`; no new package

## Premises

1. The problem is what the HMM observes, not option pricing or a trade overlay.
2. v1 is 1-D recipes in the existing settings prompt: `close_logret` (default), `parkinson`, `abs_return`, `delta_vix`, `vrp`.
3. Relabel by **mean of X** (low VIX / low VRP = calm), not by stock-return vol or by std of X.
4. Doing nothing leaves options-vol tests impossible in this repo.
5. Ship remains `python main.py`.

## Recommended Approach

B. Add `observation` to `Config`. Prompt with the five names. Build `X` per recipe. For `vrp` and `delta_vix`, also download `^VIX` and inner-join. Relabel by ascending mean of `X`. Print recipe units plus equity mean/vol in the regime profile and last-10.

## Success Criteria

- Default Enter path still matches today's close-return model
- `vrp` banner names the recipe; strip is not identical to close-return
- Regime profile lists equity mean/vol per state
- Bad recipe / missing VIX fail with a visible ValueError
